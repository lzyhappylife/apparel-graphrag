# 服装证据图谱数据补齐路线

这份路线按照当前工作台的真实拒答和部分回答结果整理。目标不是让系统对所有问题都强行回答，而是让每个回答都能回到适用范围、产品、批次、订单和来源证据。

## 一、图中五个问题的当前缺口

| 问题 | 当前表现 | 缺少的证据层 | 优先级 |
|---|---|---|---|
| 这件 SKU 的再生材料声明能追溯到哪份证书？ | 无法形成证据链 | SKU/BOM → 材料批次 → 纱线批次 → Scope Certificate → Transaction Certificate → 订单 | P0 |
| 面料批次和检测报告如何关联？ | 只能回答“存在关联”，不能说明匹配规则 | 实验室送检单、样品编号、批次号、报告编号、取样记录、LIMS 字段 | P0 |
| 面料规格变化后哪些文件需要更新？ | 能回答 Tech Pack/BOM 关联，但缺少订单和版本影响 | ECR/ECO 变更单、版本、审批、订单变更、洗标、包装、DPP、供应商确认 | P0 |
| 如何判断某面料是否满足 REACH 限制？ | 能回答原则，不能做完整产品级判断 | 当前 REACH 条目、适用产品类别、RSL/SVHC、SDS、检测方法、报告范围和批次 | P0 |
| 某供应商的工厂、认证和订单能否形成证据链？ | 只有供应链尽调背景，缺少企业主数据 | 供应商主档、工厂主档、认证范围、审核、订单、分包商、装运和批次 | P0 |

## 二、第一批必须补的资料包

### P0-1：再生材料认证与交易链

每个真实 SKU 至少补齐：

- SKU、款式、BOM 和材料成分
- 材料批次、纱线批次、面料批次
- 供应商和加工工厂主档
- Scope Certificate（范围证书）
- Transaction Certificate（交易证书）
- 证书编号、签发机构、有效期、覆盖产品、覆盖工厂、覆盖交易日期
- 采购订单、送货单、发票或出货记录
- 上游输入材料的 TC 引用
- 认证声明在商品详情、洗标和 DPP 中的使用位置

Textile Exchange 的交易证书政策要求 TC 具有唯一编号，并记录输入交易证书、认证机构和适用标准等字段。适合把证书拆成“证书主表 + 产品覆盖表 + 工厂覆盖表 + 交易关联表”，不要把整张 PDF 只当成一段文本。[Transaction Certificate Policy](https://textileexchange.org/app/uploads/2020/08/ASR-104-V3.0-Policy-for-Transaction-Certificates.pdf)

建议新增实体和关系：

```text
SKU --使用--> 材料批次
材料批次 --来自--> 纱线批次
纱线批次 --被证明--> Transaction Certificate
Transaction Certificate --引用--> Scope Certificate
Scope Certificate --覆盖--> 生产工厂
Transaction Certificate --对应--> 采购订单
证书 --有效于--> 交易日期
证书 --覆盖--> 产品/工艺/成分
```

### P0-2：面料批次与实验室报告

需要同时导入以下文件，才能回答“如何关联”而不靠猜测：

- 送检委托单
- 取样记录和样品照片
- 样品编号、面料批号、颜色、规格、卷号
- 实验室检测报告
- 检测报告原始数据或附页
- 实验室资质和 ISO/IEC 17025 信息
- 供应商 COA / 出厂检验报告
- 来料检验记录
- 不合格处理和复测报告

需要把以下字段设为可检索的结构化字段：

`report_id`、`sample_id`、`material_lot_id`、`roll_id`、`supplier_id`、`test_date`、`sampling_date`、`lab_id`、`method`、`result`、`unit`、`limit`、`conclusion`。

图谱关系应能表达“报告覆盖哪个样品”，再由样品回到面料批次；只有报告中出现“面料批次”四个字，不足以证明它覆盖当前 SKU。

### P0-3：规格变更与影响传播

需要补一套真实的版本化业务文件：

- Tech Pack v1/v2/v3
- BOM 版本和物料替代记录
- ECR/ECO 变更申请、变更原因和审批人
- 面料规格、克重、成分、颜色和供应商变更
- 打样记录、首件确认和 PP sample 批准
- 采购订单和交期变更
- 洗标、包装、吊牌和商品详情变更
- QC 检验标准、AQL、测试项目变更
- DPP 或可持续声明更新记录
- 供应商已读、确认和执行日期

需要新增“影响传播”查询：

```text
规格变更
→ 受影响 BOM 行
→ 受影响供应商和订单
→ 受影响检测项目
→ 受影响洗标/包装/商品详情
→ 受影响 DPP 字段
→ 待重新批准的样品和 QC 标准
```

### P0-4：REACH/RSL/MRSL 合规证据

不要只导入一份 REACH 摘要。至少需要四层资料：

1. **法规层**：REACH Annex XVII 当前条目、SVHC Candidate List、适用日期和产品范围。
2. **企业规则层**：品牌 RSL、供应商 MRSL、限值、检测方法和市场版本。
3. **化学品层**：SDS、化学品清单、染料/助剂、CAS 号、供应商和使用工序。
4. **产品证据层**：样品、面料批次、报告、结果、限值、实验室和结论。

ECHA 的 Annex XVII 对物质、混合物和物品设有限制，部分条目涉及服装、床品、毛巾、帽子以及纺织和皮革着色物质。[ECHA REACH Annex XVII](https://echa.europa.eu/documents/10162/bd51087b-9917-b018-69ac-d7594315e2a9)

判断逻辑应分成：

```text
产品类别是否适用
→ 目标市场法规版本
→ 受限物质/CAS 是否出现在材料或化学品清单
→ 报告检测项目是否覆盖该物质
→ 样品/批次是否对应当前 SKU
→ 结果是否低于该条目适用限值
→ 是否有有效期、例外或复测要求
```

如果只找到“REACH 合规”字样，系统应标记为供应商声明，不能自动升级为当前批次的实验室合规结论。

### P0-5：供应商、工厂、认证和订单

需要建立供应商和工厂主数据，而不是只存供应商名称：

- 供应商 ID、法定名称、贸易名称、国家/地区
- 工厂 ID、地址、生产工艺、产能、联系人
- 供应商与工厂的委托关系
- 分包商和实际生产地点
- 认证类型、证书号、范围、有效期、覆盖工艺和产品
- 审核报告、问题、CAPA、关闭日期
- 订单、生产计划、交货、出货和批次
- 供应商确认、变更通知和异常记录

OECD 强调服装鞋类供应链具有多层级、跨地域和分散特点，供应商评估需要与持续监测和整改协作结合。[OECD 服装与鞋类供应链尽调](https://www.oecd.org/en/topics/sub-issues/due-diligence-guidance-for-responsible-business-conduct/responsible-garment-and-footwear-supply-chains.html)

## 三、第二批建议补的资料

### 出口和标签

- 目标市场纤维成分标签法规
- 洗标和护理标签规范
- 原产地规则
- HS Code、TARIC 或其他商品编码
- 合格声明、装箱单、商业发票、原产地证明
- 目的地市场的儿童产品、阻燃、禁限用物质要求

欧盟纺织品标签规则要求标签和标记耐久、易读、可见并牢固附着，且在成员国市场提供时要符合语言要求。[Regulation (EU) No 1007/2011](https://eur-lex.europa.eu/legal-content/EN/ALL/?uri=celex%3A32011R1007)

### 化学品和染整

- ZDHC MRSL 版本和化学品等级
- ZDHC Gateway 或等效化学品资料
- 染料、助剂、印花浆料清单
- 化学品进厂、领用、配方和废弃记录
- 废水、污泥和排放检测
- 化学品替代和整改记录

ZDHC MRSL 是持续更新的有害物质清单，适合与化学品清单、供应商、工序和检测报告建立版本化关系。[ZDHC MRSL](https://www.roadmaptozero.com/mrsl)

### 质量与售后

- 尺寸表、版型和 grading 规则
- 面料物性测试：耐磨、色牢度、缩水、起球、撕裂、强力
- 首件、巡检、终检和 AQL 结果
- 客诉、退货、返修和召回
- 缺陷图片、缺陷代码和工序
- CAPA 和复测结果

## 四、图谱和问答能力还应补的方向

### 1. 从“拒答”升级为“缺证据清单”

当前系统在无证据时会拒答，但下一步应返回：

- 已找到的证据
- 缺少的证据类型
- 建议导入的文档
- 缺少的关键字段
- 需要人工确认的冲突
- 可以继续回答的最小问题

例如：

> 当前不能证明 XJ-2401 的再生材料声明。缺少：交易证书编号、证书有效期、覆盖的纱线批次、当前采购订单和证书与订单的对应关系。

### 2. 增加证据等级

建议给每条证据加上：

- 法规/标准原文
- 第三方认证
- 实验室报告
- 企业制度
- 供应商声明
- 订单/生产记录
- 推断关系

回答时显示“证据等级”和“是否足以证明当前产品”，避免把不同可信度的资料混在一起。

### 3. 增加有效期和时间点

证书、法规、报告和订单都需要时间属性：

- 生效日期
- 失效日期
- 签发日期
- 检测日期
- 生产日期
- 出货日期
- 版本日期

图谱查询必须支持“在某个交易日是否有效”，而不是只问“有没有这张证书”。

### 4. 增加冲突和覆盖检查

自动发现：

- BOM 成分与检测报告成分不一致
- Tech Pack 供应商与订单供应商不一致
- 证书有效期不覆盖出货日期
- 报告批次与当前订单批次不一致
- 洗标材质与产品数据库不一致
- 同一 SKU 存在多个未解释版本

### 5. 增加表格和结构化文件接入

真实服装资料大量来自 Excel、PLM、ERP、LIMS 和供应商门户。下一步优先支持：

- Excel 保留工作表、行号、列名和单元格坐标
- PDF 表格保留表头和行列关系
- 图片报告保留页码、样品号和二维码
- 邮件保留发件人、时间、附件和回复链
- 每个字段保存原始位置和解析置信度

## 五、推荐的补数顺序

1. 先补 1 个真实 SKU 的完整证据包，打通证书、批次、报告、订单和工厂。
2. 再补同一供应商的多个订单和多个批次，验证图谱能否区分范围。
3. 再补一个规格变更案例，验证影响传播和版本冲突。
4. 再补一个 REACH/RSL 失败和复测案例，验证拒答、整改和复测链。
5. 最后扩展多个品牌、供应商和市场，进入多租户权限和数据隔离。

第一阶段的验收标准不是“所有问题都有回答”，而是：

- 证书和订单能按有效期、批次和覆盖范围匹配
- 报告只能证明它实际覆盖的样品和批次
- 规格变更能列出受影响的文件、订单和检测项目
- 证据不足时能生成可执行的补证清单
- 不同证据等级不会被混成同一个结论
